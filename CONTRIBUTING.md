# Contributing

Contributions are welcome through GitHub issues and pull requests.

## Recommended workflow
1. Fork the repository.
2. Create a feature or fix branch.
3. Reproduce the reference environment and benchmark before changing the model.
4. Make one focused change.
5. Document any changed physics, numerical parameters, package versions, or OSCER resources.
6. Include new reference data when a numerical result changes.
7. Open a pull request describing the change and how it was validated.

The canonical `main` branch is maintained by the repository owner. Public visibility and an open-source license do not grant direct write access to the canonical repository.
